From the ground up

One module climbing to one feature

The same request travels up six layers — each a small, focused piece of code — until it becomes the experience you actually use.

1
Single module

📐 Embeddings

services/embeddings.py — a local fastembed model (bge-small-en-v1.5, 384‑dim, ONNX on CPU). Turns any string into a vector. No API key, no GPU, no torch.

↓
2
Storage primitive

🗄️ Vector store

services/vectorstore.py — inserts those vectors into Postgres and runs one indexed cosine query (embedding <=> :q) with an HNSW index to fetch the top‑k nearest chunks.

↓
3
Provider abstraction

🤖 LLM Router

services/llm/router.py — one LLMProvider interface behind a router that tries Claude first and transparently falls back to OpenAI — but only before the first streamed token, so an answer is never torn in half.

↓
4
Orchestration

🧠 RAG service

services/rag.py — embeds the question, retrieves chunks, builds a grounded prompt with [p.N] page markers, streams the answer, and logs provider, tokens & latency to query_logs.

↓
5
API surface

🔌 Streaming endpoint

api/routes/query.py — a thin controller exposes POST /documents/{id}/query/stream as Server‑Sent Events: one sources event, many delta events, one done.

↓
6
High-level feature

💬 Chat with your document

The ChatPanel in Next.js consumes the stream, rendering tokens live with a Sources panel and the answering provider. That's the whole journey — module 1 made this possible.

The building blocks

Every module, at a glance

Thin controllers, all the logic in focused services. Here's what each piece owns.

📝

Text Extractor

extraction/text_extractor.py

PyMuPDF reads selectable text straight from digital PDFs. Fast and cheap.

🔍

OCR Extractor

extraction/ocr_extractor.py

poppler → YOLOv8 layout detection → Tesseract per region. For scanned pages.

👁️

Vision Extractor

extraction/vision_extractor.py

Sends page images to the LLM. Best for complex layouts, charts and tables.

✂️

Chunking

services/chunking.py

Per-page recursive character splitter with overlap, preserving page numbers.

⚙️

Ingestion Pipeline

services/pipeline.py

extract → chunk → embed → store, run off the request path as a background task.

🔐

Auth & Security

core/security.py

JWT access + refresh tokens, password hashing, plus optional API-key access.

🧾

Data Model

models/*.py

users · documents · chunks · query_logs — relational rows and vectors in one store.

🪢

Correlation Logging

core/logging_config.py

Every request gets an id attached to all logs and returned as X-Request-ID.

The heart of retrieval

One indexed query does the work

No separate vector database to keep in sync — chunks and their embeddings live together in Postgres.

SELECT * FROM chunks WHERE owner_id = :owner AND document_id = :doc ORDER BY embedding <=> :query_embedding -- cosine distance, HNSW index LIMIT :k;
Why it's nice to use

High-level features

Everything above adds up to a handful of things you actually feel.

🎛️

Pick your extraction

Text, OCR or Vision — per upload. The speed‑vs‑robustness‑vs‑cost trade-off stays in your hands.

📑

Cited, grounded answers

Answers use only your document's context and cite [p.N]. If it isn't in the doc, it says so instead of inventing.

⚡

Live streaming

Tokens arrive over SSE as they're generated, with an expandable Sources panel and the provider that answered.

🛟

Automatic fallback

Claude is primary; if it errors or rate-limits before the first token, OpenAI takes over seamlessly.

🔐

Multi-user & secure

JWT auth scopes every document and chunk to its owner — your files and questions stay yours.

📊

Observable by default

Every answer logs provider, tokens and latency; every request carries a correlation id end to end.
